# Week 3: Image Curation Strategy — Review Draft

> **Evidence boundary:** This is a curation plan for the existing portfolio, not a completed image set. No personal photo, synthetic image, or participant-selected work screenshot is presented as if it had been supplied or personally approved. The participant must make and document the final visual selections.

## Visual direction already used

The portfolio is intentionally image-light. Its visual system uses DM Serif Display, IBM Plex Sans, dark ink, warm paper, acid green highlights, typography scale, spacing, and simple borders to create a consistent interface. This avoids using AI images as stand-ins for actual engineering work.

## Real capture standards

Each selected work capture should be legible at normal desktop and mobile sizes, cropped to the evidence rather than an entire cluttered screen, and stripped of tokens, e-mail addresses, private keys, local filesystem details, or unrelated tabs. One project should have one clear visual claim. A code editor screenshot is useful only when it shows the relevant tested decision; a terminal output is useful only when the command and result are readable.

## Generated-image decision

No generated visual is included in the current portfolio. That is a deliberate rejection, not an omission: an abstract AI hero texture would add visual surface but would not strengthen the proof of backend work. If a future release needs icons or a texture, the participant should generate a small coherent set using the existing palette and describe the prompt/version used. It must not replace any work capture or personal photo.

## Required participant curation record

- [ ] Add the approved real captures to the portfolio from a source the participant controls.
- [ ] If adding a portrait, use a real current photo and confirm consent for public display.
- [ ] Write a genuine one-to-two sentence rejection note for a candidate image the participant reviewed and declined; state the specific mismatch (for example, unreadable evidence, inconsistent mood, wrong crop, or an AI stand-in for real work).
- [ ] Recheck each added image at mobile width and ensure it has accurate alt text.

This plan is not a substitute for the assignment’s final keeper set and participant-authored rejection note.
